# 작업 내역

OpenCAD 2D 뷰어를 만들어 온 과정을 단계별로 정리했습니다. 커밋 하나하나는 `git log`에, 남은 일은 [ROADMAP.md](ROADMAP.md)에 있습니다.
모든 기능은 브라우저 안에서만 동작하며, 연 파일은 사용자 컴퓨터 밖으로 나가지 않습니다.

## 2026-10-16 (2): 큰 도면 정점 평탄 좌표·워커 문서 부호화

큰 도면의 문서 메모리와 GC, 워커가 문서를 보내는 시간을 줄였습니다. 합성 100만·300만 객체 DXF로 쟀고, 저장 결과(DXF·DWG)와 장면 그림의 지문은 고치기 전과 같습니다(100만 DXF `66a2d13a0eb5fbd0`·DWG `bc5d69323b08d885`·장면 `db866df2c5f7dc92`, 300만 DXF `231005554c3d04af`·장면 `5ffd8919102f920a`).

### 정점 평탄 좌표
- 경량 폴리선(LWPOLYLINE) 정점을 정점마다 객체로 두지 않고 수 배열 `verts` [x, y, 볼록, …]와 `widths` [시작 폭, 끝 폭, …](모두 0이면 없음)로 둡니다. 해치 폴리선 경계도 `verts` 하나로 둡니다.
- 읽기·쓰기·장면 빌더는 배열을 바로 읽고, 편집 계산은 `src/core/lwpoly.ts`의 도우미로 정점을 풀어 쓴 뒤 되담습니다.
- Float64Array 대신 보통 수 배열을 썼습니다. 객체마다 형식 배열을 두면 ArrayBuffer 몫으로 폴리선 하나에 150B 넘게 더 들고 화면 스레드에서 되살리기도 느렸습니다. 구조화 복제는 수 배열의 수를 하나씩 상자에 담으므로 객체 복제(cloneEntity)와 워커가 받는 편집에서 평탄 좌표를 다시 담습니다.
- 100만 객체: 읽은 뒤 문서 힙 670MB → 555MB(경량 폴리선 하나 717B → 605B, 해치 1,409B → 1,049B), 읽기 최대 메모리 1,314MB → 1,029~1,175MB, 장면 만들기 중 GC 1.85초 → 0.94~1.40초(기계 부하 4~60에서 잼, 시간 값은 부하에 따라 흔들림). 300만 객체: 읽은 뒤 문서 힙 1,848MB → 1,504MB, 최대 메모리 5,917MB → 4,695MB.

### 워커 문서 부호화
- 속성 모양마다 속성을 이름으로 바로 읽는 쓰기 함수를 만들어 씁니다(속성 읽기가 한 모양만 보고, 수 값을 상자에 담지 않습니다). 수만 든 배열(평탄 좌표·매듭 등)은 값마다 태그를 쓰지 않고 이어 적고, 화면 스레드는 꼭 맞는 크기의 실수 배열로 되살립니다.
- 100만 객체 모형 공간 부호화(묶음을 넘겨 버리는 실제 조건, 같은 부하에서 번갈아 잼): 0.90~1.01초 → 0.68초, 장면 전에 처음 만질 때 1.23~1.48초 → 0.85~0.99초.
- 화면 스레드가 문서를 받는 CPU는 1.85초 → 1.03초, 메시지 하나에 멈추는 가장 긴 시간은 371ms → 65ms가 됐습니다(300만 객체 541ms → 157ms).

### 남은 일
- 2D·3D POLYLINE 정점(객체 하나 1,266B), 스플라인 제어점·맞춤점, 해치 모서리(선·호) 경계, 지시선·메시 정점은 아직 객체 배열입니다. 남은 문서 메모리의 대부분은 객체 자체의 공통 속성과 점 객체(선 하나 360B)입니다.

## 2026-10-16: 3D 뷰어 — NC·STEP·SKP

로드맵의 "다른 형식"을 같은 저장소에서 시작했습니다. NC·MPR·Heidenhain·STEP·SKP 파일을 열면 2D 도면과 같은 파일 탭에 3D 문서로 열립니다.
모두 서버 없이 브라우저 안(웹 워커)에서 읽습니다. 다른 3D 엔진이나 형식 라이브러리를 쓰지 않고 공개 명세·공개 자료 파일만 보고 새로 작성했습니다.

### 3D 뷰어
- WebGL2로 직접 만든 뷰어: 왼쪽 끌기 회전, 가운데·오른쪽 끌기 이동, 휠 확대, 뷰 큐브와 표준 뷰(위·앞·오른쪽·등각), 원근·평행, 음영·윤곽·와이어프레임·X-ray, 측정, 그림 저장.
- 실제 GPU에서 선분 300만 개·삼각형 100만 개를 끌어도 끊기지 않습니다.

### NC
- G-code(ISO·Fanuc·LinuxCNC·GRBL·Mach3 방언 자동 판별): 직선·호·나선, 평면·단위·좌표계, 고정 사이클, 부프로그램, 변수와 IF/WHILE.
- Heidenhain 평문(.h)과 woodWOP MPR(공작물, 수직·수평 드릴, 윤곽 가공, 홈, 포켓, 꺼진 가공).
- 패널: 코드 보기(경로를 고르면 그 줄로, 줄을 누르면 그 경로 강조), 공구 목록·켜고 끄기, 통계·예상 시간, 재생(공구 위치 표시, ×1·×10·×100).
- 100만 줄(32MB) G-code를 약 0.5초에 읽습니다.

### STEP
- AP203·AP214·AP242의 B-rep(평면·원기둥·원뿔·구·원환·B-스플라인·회전·밀기 곡면)을 틈 없이 삼각화하고, 조립·색·단위를 읽어 제품 나무로 보입니다.
- 공개 STEP 21개를 실패 면 없이 읽었고, NIST 시험 모형 9개는 모두 틈이 없습니다.

### SKP
- SketchUp 2021~2026 파일의 면(구멍 포함)·모서리·재질 색·그룹/컴포넌트·태그를 읽습니다. 공개 표본 파일의 바이트만 보고 분석했습니다(docs/formats/skp.md).
- 2020 이하 파일은 형식이 완전히 달라 아직 읽지 못하고 안내합니다.

### 이 단계의 한계
- NC의 회전축(4·5축)·선반 코드, 반경 보정 경로, STEP 와이어프레임·PMI, SKP 무늬는 아직 그리지 않습니다.
- 실제 휴대폰 기기와 큰 실물 파일로 더 확인해야 합니다.

## 2026-10-15 (9): 빠진 AutoCAD 명령 채우기

블록·참조, 편집·표시, 파일·출력 세 갈래로 아직 없던 AutoCAD 2D 명령을 채웠습니다.

### 블록·참조
- 속성 내보내기·가져오기(ATTOUT·ATTIN), 속성 추출(ATTEXT, CDF·SDF·DXF와 템플릿), 속성 유지 재정의(ATTREDEF).
- 외부 참조·이미지·PDF 부착(XATTACH·IMAGEATTACH·PDFATTACH), 의존 기호 결합(XBIND), 참조 열기(XOPEN), 블록을 외부 참조로(BLOCKTOXREF).
- 블록 팔레트(BLOCKSPALETTE), 선택하여 붙여넣기(PASTESPEC), 치수 스타일 내보내기·가져오기(DIMEX·DIMIM), UNDEFINE·REDEFINE·BASE·TINSERT.

### 편집·표시
- 해치 경계 만들기·다시 정하기·원점 바꾸기, 이미지·PDF 조정과 PDF 도면층 켜기·끄기.
- 표 CSV 내보내기(TABLEEXPORT), 셀 특성 일치(MATCHCELL), 빠른 특성(QUICKPROPERTIES), 그룹 편집(GROUPEDIT), DBLIST·DIMCENTER·PLAN·ELEV 등.
- 신축(STRETCH)이 걸침 폴리곤을 받고, AutoLISP regapp의 등록이 명령 취소로 되돌아갑니다.

### 파일·출력
- 모두 닫기·모두 저장·되돌리기(CLOSEALL·SAVEALL·REVERT).
- 플롯 스탬프(PLOTSTAMP), 플롯 스타일 지정·변환(PLOTSTYLE·CONVERTCTB·CONVERTPSTYLES).
- 배치 설정(MVSETUP, ISO 제목 블록)과 배치 마법사(LAYOUTWIZARD), WMF 내보내기(WMFOUT), 가져오기(IMPORT).

### 이 단계의 한계
- TINSERT는 표 셀 안이 아니라 셀 자리에 맞춘 블록 참조로 넣습니다. DIMEX의 .dim은 AutoCAD Express 실물과 다를 수 있습니다.
- PDF 언더레이의 대비 값과 IMAGEQUALITY·VIEWRES는 저장하지만 화면에는 반영하지 않습니다.

## 2026-10-15 (8): AutoCAD 구속 쓰기·동적 블록 평가·선택 방식·휴대폰 배치

PR 스쿼시 머지로 배포한 두 번째 묶음입니다.

### 구속·연관 배열
- 이 앱에서 만든 구속을 AutoCAD 2D 구속 그룹으로 저장해 AutoCAD에서도 구속으로 보입니다. 저장한 파일을 다시 읽으면 같은 구속으로 나옵니다(DXF·DWG 여러 버전 왕복).
- 같은 반지름 구속을 읽고 고치고 씁니다(공개 DWG로 확인).
- 곡선(호·원·폴리선·스플라인) 경로 연관 배열도 AutoCAD 형식으로 저장합니다. 공개 도면의 경로 배열 73개에서 AutoCAD가 저장한 곡선 자료와 같게 나왔습니다.

### 동적 블록
- 배열 동작을 평가해 사본을 다시 만듭니다. AutoCAD가 공개 도면에 만든 결과와 사본 수·자리가 같습니다.
- 정렬 매개변수 그립을 끌면 근처 선·곡선의 방향으로 블록이 돕니다.
- 구속 기반 동적 블록의 매개변수 값을 바꾸면 블록 안 형상이 구속을 지키며 따라옵니다.

### 스크립트·AutoLISP
- 객체 선택에서 윈도우 폴리곤(WP)·걸침 폴리곤(CP)·울타리(F)를 씁니다(명령·스크립트·ssget).
- LAYOUT의 템플릿(T)·다른 이름으로 저장(SA). 배치 탭 오른쪽 클릭 메뉴에도 있습니다.
- AutoLISP의 확장 데이터·사전 함수, nentsel·textbox·osnap·grdraw.

### 화면 배치
- 휴대폰·좁은 창에서는 리본이 도면 위에 겹쳐 펼쳐지고, 팔레트가 아래쪽 시트가 되며, 소프트 키보드가 올라오면 명령행이 따라 올라갑니다.
- 상태 막대가 넘치면 덜 쓰는 항목을 ⋯ 메뉴로 옮깁니다. 데스크톱 배치는 그대로입니다.

### 이 단계의 한계
- 각도·대칭·부드러움 구속, 블록 속성 표, 일부 값 목록은 실물이 없어 원본 보존만 합니다.
- 실제 휴대폰 기기와 AutoCAD로 직접 열어 본 확인은 아직 없습니다.

## 2026-10-15 (7): 공개 도면으로 확인한 AutoCAD 형식

표본 폴더에 없는 기능의 형식을 GitHub 등에 공개된 AutoCAD 도면 파일(DWG·DXF)로 확인해 넣었습니다. 도면 파일만 읽었고, 그 저장소의 코드는 보지 않았으며, 내려받은 도면은 저장소에 두지 않았습니다. 이 단계의 커밋은 `40738df`부터입니다.

### 파라메트릭 구속과 연관 배열
- AutoCAD에서 만든 파라메트릭 구속을 읽어 구속 막대·매개변수 관리자에 보이고, 형상을 고치면 이 앱 해법기로 따라갑니다. 고친 값·식·삭제는 AutoCAD 원본 구속 망에 같은 형식으로 저장합니다.
  - 기하 구속 11종(일치·점-곡선·평행·직교·수평·수직·접선·동일선상·동심·동일·고정), 수평·수직·정렬 거리와 반지름·지름 치수 구속, 변수.
  - 공개 도면의 AutoCAD 구속 759개를 읽어 모두 지금 형상에서 만족되는 것을 확인했습니다.
- 새로 만든 연관 배열(직사각형·원형·선 경로)을 AutoCAD 연관 객체로 저장해 AutoCAD에서도 연관 배열로 보입니다.
- DWG 안의 AutoCAD 연관 객체(배열·구속)를 해독하고 씁니다. 공개 DWG·DXF 짝의 연관 객체 1011개를 비트 단위로 왕복해 확인했습니다.

### 동적 블록
- DWG 동적 블록 객체를 9종에서 30종으로 늘렸습니다. 이제 DWG로 연 뒤집기·XY·회전·조회·점·극좌표·정렬·기준점 정의를 편집하고, 다른 버전으로 저장해도 정의가 남습니다.
- 표본·예제·공개 짝 도면의 동적 블록 객체 1,954개 가운데 1,948개가 남는 비트 없이 풀립니다.

### 도면층 필터·CAD 표준
- 도면층 필터를 AutoCAD 형식으로 읽고 써서 AutoCAD에서 만든 필터가 보이고, 이 앱에서 만든 필터도 AutoCAD에 보입니다. 바꿀 수 없는 필터 식은 읽기 전용으로 보존합니다.
- CAD 표준 연결을 AutoCAD 형식으로 저장하고, 도면층 변환기(LAYTRANS)가 표준 파일(DWS)의 매핑을 불러오고 저장합니다.

### 주석 축척
- 명세만 보고 정했던 치수·MTEXT 레코드 배치를 실물과 맞췄습니다. 전에는 풀지 못하던 AutoCAD 치수·MTEXT 축척 레코드를 이제 읽고 그대로 저장합니다.
- 주석 해치는 AutoCAD처럼 뷰포트별 표현 레코드(HATCHVIEW)를 함께 저장합니다.

### 이 단계의 한계
- 실물이 없던 구속(각도·대칭 등)이 든 구속 그룹, 지운 배열 항목 플래그, 일부 동적 블록 값 목록은 원본 그대로 보존만 합니다.
- 이 앱이 새로 만든 구속은 아직 AutoCAD에서 보이지 않습니다.
- AutoCAD로 직접 열어 본 확인은 아직 없습니다.

## 2026-10-15 (6): 큰 도면 점진 빌드·문서 전송·묶음 무리

큰 도면을 열 때 기다리는 시간과 화면이 멈추는 시간을 줄였습니다. 이 단계의 커밋은 `a497c0a`부터입니다. 합성 100만 객체 DXF(203MB)로 쟀고, 저장 결과와 장면 그림은 고치기 전과 바이트까지 같습니다.

### 점진 빌드
- 장면을 다 만들기 전에 그림부터 보입니다. 워커가 장면을 만드는 동안 약 1초마다 그때까지의 그림을 조각으로 보내고, 화면은 진행 상자 뒤에 받는 대로 겹쳐 그립니다.
- 저장된 첫 화면(*Active 뷰)이 도면 일부만 보이면 그 안의 객체를 먼저 그려 보냅니다.
- 조각에는 첫 화면 밖의 묶음, 반 픽셀보다 작은 객체의 나머지 선분, 너무 작아 그리지 않을 글자를 넣지 않습니다(100만 객체 전체 보기에서 조각 264MB → 109MB).
- 브라우저에서 같은 파일을 열 때 파일을 다 읽은 뒤 첫 그림까지 약 10.8초 → 0.35초, 열기가 끝날 때까지 약 10.8초 → 5.3초가 걸렸습니다.

### 메인 문서 사본
- 문서를 장면 뒤에 보냅니다. 객체가 많은 블록(대개 모형 공간)의 객체는 5만 개씩 묶어 부호화합니다. 같은 속성 모양은 한 번만 적고, 수·문자열 표·바이트 배열은 형식 배열로 옮깁니다. 나머지는 예전처럼 구조화 복제로 보냅니다.
- 화면 스레드는 묶음을 받는 대로 풀어 붙이고 핸들 색인을 조금씩 채웁니다. 예전에는 문서를 한 번에 역직렬화하느라 약 7초(부하가 높을 때 30초 넘게) 멈췄지만, 이제 메시지 하나에 대개 40~120ms입니다. 화면 스레드의 문서 메모리도 약 770MB에서 590MB로 줄었습니다.
- 색인을 블록에서 다시 만들 수 없거나 부호화하지 못하는 값이 있으면 예전 방식으로 보냅니다.

### 묶음 그리기 호출
- 전체 보기처럼 멀리서 볼 때는 작은 묶음을 도면 크기 1/8 칸마다 합친 무리로 한 번에 그립니다. 크게 확대해 무리의 일부만 보이면 원래 묶음을 필요할 때 GPU에 올려 그리고, 오래 쓰지 않으면 내립니다.
- 100만 객체 전체 보기에서 선·채우기 그리기 호출이 10,811번에서 116번으로 줄었습니다(묶음 9,010개 → 무리 32개와 큰 묶음). 남은 병목은 GPU의 정점 처리입니다(한 장에 약 65ms).
- 편집으로 숨긴 객체는 무리 버퍼에도 반영합니다. 무리로 그린 화면과 묶음으로 그린 화면은 픽셀 몇 개만 다릅니다(깊이가 같은 곳의 그리는 순서 차이).
